## Deferred extensions

- **02:** Cross-user verification attestations and separate trust sync.
- **06:** Expiring approval needs reliable clocks and renewal by approvers that stop renewing withdrawn selections. Per-grant approval needs an online trusted approver, issuer nonce, exact selection/epoch, deadline, and replay protection. A fresh response alone proves neither current authority nor consent; any delay bound must state its assumptions.
- **08:** Dedicated recovery-key authority and cross-application backup portability.

<a id="todo-13"></a>
### 13: Authenticated streaming

Large media, seeking, or early playback needs a separate versioned format authenticating chunk order/count, total length, object identity, and final manifest. Test truncation and cross-object substitution; [Format 1](core.md#encrypted-blobs) requires bounded whole-file authentication.

## Validation cases

Each row requires implementation evidence; prose/link checks do not satisfy it. Conformance vectors MUST include exact inputs, ordered observations, starting local state, expected result/reason, durable state changes, and permitted network/key-release actions. Cross-implementation comparisons use the same local history; different observed histories need not produce identical authorization decisions.

| Area | Required cases |
| --- | --- |
| Encoding and cryptography | Fingerprints, verification payload/code, all signing domains, CID/CBOR normalization, grant headers/manifests, HPKE suites/lengths, commitments, record/blob/history AAD, history-wrap lengths and nonce separation; malformed/duplicate/unknown fields, signatures/points/all-zero KEM inputs, altered contexts, account/space/location substitution, no suite fallback, finite limits, full authentication before plaintext. |
| Format 1 framing and padding | Use `com.example.peep.envelope` consistently and reject other envelope types. Records and blobs use the same CBOR frame of two byte strings with empty or nonempty zero-filled padding; all readers support both. Round-trip binary files (including empty files and trailing zero bytes) and normalized record maps; exercise CBOR length boundaries and default/custom size buckets. Reject wrong arity/types, nonzero padding, non-normalized encoding, trailing bytes, truncated or oversized declared lengths, and unframed content; no fallback. Authenticate before frame parsing or content release, preserve record schema checks, and enforce padded ciphertext/full-blob limits before allocation. Ciphertext length is frame length plus 16; blob CID/size cover the entire encrypted envelope. No outer original-length field; counts, timing, blob relationships, and padded sizes remain visible. Grant/history-wrap plaintexts are unchanged. Include byte-exact positive/negative vectors and independent review. |
| Default padding | Minimum 256-byte ciphertext and increasing power-of-two buckets include both byte-string headers, the array header, payload, padding, and 16-byte tag. Select the smallest attainable bucket; skip header-length gaps (a 212-byte payload cannot produce 256-byte ciphertext and uses 512 with 278 padding bytes). Cover empty payloads, exact buckets, every header boundary, and bounded arithmetic before allocation. Check outer record/envelope and transport limits: use empty padding when no bucket fits, reject if even that exceeds a limit. Readers accept other valid sizes. Shared defaults reduce only padding-specific fingerprints; visible collections and metadata remain exposed. |
| Blob references | After record authentication/schema validation, check nested maps/arrays for complete blob references matching authenticated envelope entries, including CID, MIME type, and size. Reject missing references and same-CID metadata mismatches before content use; ordinary CID links do not require blob entries, and extra envelope entries remain permitted. Modified/reordered outer lists fail AAD authentication; original file metadata stays inside encrypted content. |
| Locally current state | Withheld newer declarations, membership, or configuration leave clients using their latest authenticated local state without claiming freshness. Reordered delivery cannot regress ancestry/revisions or clear learned withdrawals; known conflicts and missing required evidence block affected operations. Apply to grant/retry/direct checks and current verification policy on first key acceptance; historical authorization still uses historical evidence. Newer learned state takes effect under existing rules. |
| Host authority | Authenticate current/historical membership/configuration/epochs through migration; credentials/writer lists are not membership or device evidence. No creator signature or issuer appointment. Any eligible enrolled holder may grant current/historical keys, including pre-join epochs; reject known removed issuers/recipients. Admission cannot bypass verified-only: unverified bindings remain blocked, while verified bindings are eligible when other checks pass. Host-controlled policy relaxation requires authenticated configuration. |
| Membership visibility | Authenticated additions, removals, readmissions, and verification-policy changes (including downgrades) become visible when learned; cover offline reconciliation, affected accounts, old/new policy, and retained-history access. Inspect grants to other members with exact bindings, issuer, membership/policy evidence, epochs, connected history, and gaps. Unexpected host-authorized membership is not a protocol violation when other checks pass. Notices add no approval gate or pre-disclosure guarantee. |
| Verification | Initial PDS substitution versus independently verified rejection; changed pins, downgrades, exact DID/device/both-key QR/full-code comparison through an independent channel. Self-signatures/PDS delivery insufficient; mismatches block until resolution. Reuse across spaces/lifecycle without repeat OOB or bypassing space authorization. |
| Approvals | Same-account additions rooted in TOFU/verified bindings, offline approver reuse, retained private provenance; reject cross-account/space substitution, missing/unanchored/cyclic approval, unjustified promotion, and another issuer's status/grant as verification. Withdrawn approvers cannot establish new bindings through backdated or unaccepted intermediate approvals. |
| Upgrades and policy | Exact-binding upgrade affects future local decisions only; preserve prior grant status and derived provenance, never revive revocations. Effective verified-only, required by the host or local floor, applies to granting and accepting current/historical keys, retries, and direct delivery; issuer and recipient each verify the other locally. One eligible issuer suffices when both checks pass. Reject a TOFU issuer even if the recipient is verified, and a TOFU recipient even if the issuer is verified; valid signatures, host activation, reported recipient trust, and successful decryption cannot bypass these checks. Missing configuration never permits fallback; tightening cannot repair disclosure or invalidate valid archives. First key acceptance from an archive still verifies the issuer; policy tightening preserves prior valid acceptances and historical grant validity. |
| Local policy floors | Exercise all host-policy/floor combinations, default-disabled floors, and per-space isolation. Host downgrades cannot disable a floor; a disabled floor cannot weaken host verified-only, and missing configuration still blocks. Both parties apply their own effective policy; reject TOFU issuers or recipients where the local floor requires verification. Cover current/historical grants, retries, direct delivery, archived first acceptance, and derived keys after tightening; recheck floor changes before release/acceptance. Show host and effective policies separately. Floor settings and retained effective-policy decisions remain private; another client's compliant weaker-policy grant can disclose the shared key despite a local floor. Stricter readers may reject acceptance without marking that grant unauthorized. |
| Bootstrap and ancestry | Genuine first observation at an authenticated complete snapshot with unfetched predecessors and existing account pins/withdrawals. Retain starting refs; later updates need comparison paths. Out-of-order delivery, changed/cross-account/space edges, cycles, ancestor replay, new-root reset, and newly discovered pre-bootstrap history. Missing paths prove neither supersession nor conflict and block affected grants. |
| Selections and conflicts | Complete replacement, empty versus missing/deleted snapshot, removal by omission without revoking account-wide trust, no selection of revoked bindings. Authenticated forks pause grants to/from only the affected account/space. No merge/branch choice; accepted unwithdrawn signer can resolve while not selected. Cover every known tip, concurrent resolutions, later forks, invalid evidence, and missing ancestry. |
| Batched enrollment | One confirmation covers exact bindings, chosen spaces, and changes; each signed snapshot uses its own space/history. Reuse verification without automatic account-wide selection. Partial failure, offline spaces, retries, concurrent updates/conflicts, removal during a batch, and restart preserve other selections and the authorized scope; report incomplete publication. |
| Withdrawals | Same-account peer/self, compromised accepted signer withdrawing peers, invalid/cross-account/unknown signers, cutoffs for withdrawn signers, modified target/scope. Preserve across deletion, replay, restore, future spaces. Previously accepted bindings survive approver withdrawal subject to their own withdrawal. Relays use local trust; withheld updates never imply bounded freshness. |
| Revocation authority | Self-revocation, mutual/longer revocations, open chains, and arbitrary outgoing statements use independent per-statement checks. Permute delivery for a fixed device set accepted before any withdrawal: all valid statements take effect. After signer withdrawal, accept revocations of targets with A(target) < W(signer), including newly signed statements long afterward; reject targets accepted at/after the cutoff and known never-accepted targets. Unknown or incomparable positions remain incomplete. Active signers may revoke not-yet-accepted targets without establishing trust in them. Unknown/unaccepted/cross-account signers and invalid signatures gain no authority. Cover all older devices withdrawn, fresh replacement recovery, and clients permanently disagreeing when replacement acceptance straddles the signer's locally observed withdrawal. No approval, declaration, or grant authority is restored. |
| Rotation events | Membership removal, selection omission/empty selection, account revocation, mixed updates, current-key compromise. Additions alone or access only to old keys do not require rotation of unaffected keys. Process exact evidence before fresh generation, no reused candidate, reject context/commitment substitution. Inherit restrictions, block missing required evidence, accept valid later membership/selection but never undo exact-binding revocation. Competing epoch omitting trigger requires fresh proposal; replacement-key disclosure is a new event. Ordering/labels do not prove exclusion. |
| Activation | Competing creation/rotation/recovery: one atomic winner, stale requests never auto-activate, exact proposal/commitment, unique IDs, numbering/overflow, durable key before request. Lost replies, restarts, altered-ID reuse, retries after later rotations return original result without rollback. Losing proposals authorize neither writes nor grants. Accept keys only from issuers meeting the device verification policy, including when the issuer generated the epoch. |
| Availability | Zero/partial grants, no self-grant or recipient acknowledgments, unavailable recipients/missing enrollment evidence, later grants under current authorization. Missing active key pauses writers; content is lost only if no key copy, backup, or usable history-wrapping path survives. Host acceptance proves neither key durability nor universal delivery. |
| Availability recovery | Proposer crash, offline/withholding behavior, or sole-key loss after acceptance and before grants. Another eligible enrolled device without the active key can activate a fresh successor without a security trigger, proof of zero grants, recipient acknowledgment, or protocol-wide timeout. Cover zero/partial/unknown grant coverage, local retries/backoff, concurrent recoveries, and races with security rotation. Preserve inherited restrictions and newly known events without a new event type; missing required evidence and symmetric verified-only checks still block affected operations. Content publication waits for the accepted successor key while recovery remains permitted. Late old-key grants allow historical reading without rollback; lost-key content stays unavailable. Exercise host throttling/removal against repeated malicious activation without claiming unconditional progress. |
| Recovery scheduling | Available or requested usable grants avoid rotation; slow responses receive a bounded retrieval window with randomized backoff. Recheck the active epoch and grants before submission, including after competing activations or stale proposals, to avoid recovery cascades. Prefer a willing, eligible active-key holder when rotation remains needed and preserve its predecessor wrap; unavailable or unwilling holders do not veto recovery without that key. Unusable grants do not permanently suppress recovery. Stop unnecessary recovery attempts through T7 while preserving uncertain or late activation outcomes. Explicit user recovery may skip the window; required security rotation is not delayed. All paths retain authorization, effective verification policy, and activation checks; no host wait requirement or fixed protocol timeout. |
| Distribution scheduling | Generator-first authorization failures and crashes; helpers use randomized backoff or recipient requests, including device additions. Concurrent helpers, partial repo views, retries, and duplicates retain normal publication checks. Existing grants with unverified issuers, missing evidence, or bad ciphertext cannot permanently suppress alternatives. Requests usable without content keys remain non-authoritative, bounded hints; no exclusive issuer or complete-coverage claim. |
| Key requests | Publish unencrypted signed requests in the requester's space repo; discover through normal authenticated sync, notifications, offline catch-up, and periodic reconciliation without content keys. Reject bad schema/signature and account/space/location substitution; validate accepted epoch and exact recipient selection independently. A valid self-signed request cannot seed trust or bypass withdrawals, conflicts, effective verification policy, or grant publication/acceptance. Any/preferred issuers and requesting an alternative after an unusable grant; preferred issuer has no exclusive authority. Exact retries reuse bytes/identity; semantic deduplication, per-account bounds, randomized backoff, and reconsideration after authorization/key changes. Delete satisfied/abandoned/obsolete hints without audit gaps, evidence pruning, or a claim of receipt; exclude requests from evidence manifests. Suppression, denied access, and offline holders preserve recovery and its scheduling rules without promising delivery. |
| Backward history | A current grant unlocks reachable history without separate historical device grants; pre-join access and lazy cached traversal. Cover empty, single-predecessor, and multiple-target lists through the 64-entry limit. Reject null, oversized/unsorted lists, duplicate targets/nonces, malformed fields/lengths, nonempty creation history, cross-space/unaccepted/self/forward targets, and cycles; accepted older non-predecessor targets are valid. Bind source space/epoch/key ID/predecessor/commitment/context and exact target CID; reject substitutions, altered ciphertext/tag/nonce, wrong keys, and target-commitment mismatches. Current-key compromise exposes reachable history while old keys cannot move forward. |
| History gaps and fallback | Recovery without the predecessor key can activate with an empty list or wraps for held older keys. A later epoch wraps both the predecessor and a missing older key, repairing the gap for subsequent grants; older key holders alone cannot use the new bridge. Cover multiple gaps, shared descendants, partial repair, and more targets than the bound permits, preserving the predecessor wrap when its key is held. Missing keys or incomplete traversal do not block recovery; empty lists and valid omitted targets do not prove the generator lacked keys. No post-activation edits or supplementary wraps under existing keys. Creation ends a path normally; skipped/unavailable/invalid or budget-limited paths report gaps/failures while valid starting keys and other paths remain usable. Malformed starting metadata still fails its grant. Direct historical grants obey current authorization and symmetric verification, then traverse their own wraps. Later wraps can recover keys lost from plaintext storage; no fallback to older write epochs. |
| History audit | Starting grant verification covers all reachable history, including bridges, without trusting earlier generators or creating transferable verification. A bridge expands the new epoch's access, never that of earlier grants without a path to it. After policy tightening, prior acceptance of a TOFU starting key cannot bypass verification for first acceptance of a derived key; preserve earlier valid acceptances. Retain derived-key provenance, source/target paths, exact metadata used for issuance, and later traversal evidence, including shared targets and cached results; preserve original audit records/trust decisions. Lazy history fetch cannot excuse missing starting-grant evidence, and skipped epochs cannot be reported as complete coverage. Include vectors and independent review for the wrap-list encoding. |
| Abuse controls | Account budgets survive new device IDs; bounded queues/report processing, duplicate reports, and coalesced events preserve unresolved restrictions and immediate withdrawal enforcement. Idempotent outcomes survive throttling. Forged claims or repeated reports confer no extra authority. Permit urgent rotation and administration without a protocol-wide cooldown; repeated malicious activation and quota exhaustion have explicit availability limits. |
| Writers | Continue latest-known active epoch during pending triggers, including compromise, while withdrawals block grants. New active epoch requires switch/pause, no fallback/rollback. Fresh-nonce re-encryption of queued records/blobs; interrupted uploads/cancellation cannot undo exposure. Preserve offline reads/drafts; no global switching deadline. |
| Evidence and archives | Exact issuer/recipient declarations/keys, host decisions, accepted epoch/context, actual retained bytes when source PDS withholds; no private OOB/cross-space provenance leakage or inherited verification. Historical reading after removals/revocations still checks signatures/bindings/evidence/commitment. Missing required evidence blocks; historical uncertainty alone need not block valid decryption but timestamps do not prove ordering. Archives never restore authority or access. |
| Publication retries | Durable bytes/identity before release, evidence-first upload, crashes before/after publication/ack, identical retries give one record. Changed bytes are new issuance. Recheck both parties/policy/context/withdrawals/conflicts/evidence on retries/direct delivery, even after acknowledgment. Missing acknowledgment leaves exposure uncertain and forbids direct forwarding; stopped retries preserve published audit records. |
| Auditing | TOFU substitution detected through honest issuer repo and retained own history despite source withholding. Forged audit signatures, stale formerly authorized versus never-authorized keys, legitimate revisions, suppression/collusion, unknown history, observations versus grants. Signature attributes statement, not PDS misconduct or decryption. Review metadata and transferable-signature privacy. |
| Retention and sync | Indefinite grants, exact evidence, declarations including superseded snapshots/branches/resolutions; preserve through migration/rotation/revocation/membership/restore. Host discovery plus retained participants, former repos while authorized, audit before key delivery, interrupted checkpoints/gaps, expiry/deletion/unavailable history. Offline catch-up, retained local auditing after removal without promised further access; no all-grants-seen claim. Background gaps neither bypass grant checks nor block unrelated work. |
| Recovery/transfer | Surviving approval or independent helper verification of fresh keys, one eligible holder can restore retained epochs without transferring trust to others. Reject PDS-only replacement, fresh-TOFU fallback, revived withdrawals or re-invitation history reset. Authenticated/confidential keys plus pins/provenance/order/withdrawals/conflicts and per-space floors; older imports preserve newer known state. Floors survive restart, leaving/rejoining, and host migration. Merge floors using the stricter value; only explicit local user action disables one. Known missing floor state requires recovery or an explicit choice before TOFU; undetectable backup rollback retains its stated limits. Missing/incomparable history cannot invent prior acceptance; key-only restore cannot recreate trust; all copies and wrapping paths lost means plaintext lost. |

### Procedure and transition coverage

| Procedure | Required mapping and additional cases |
| --- | --- |
| [G1–G6: exchange authorization](core.md#grant-authorization) | Host authority, verification, selections, withdrawals, and locally current state. Both local roles and their effective policies/floors; known denial versus missing evidence; valid readmission/reselection restores eligibility but never a revoked binding; no release before `OK`; authorization changes between validation and release. |
| [A1–A7: grant acceptance](core.md#grant-acceptance) | Encoding, policy, evidence/archives, and history audit. No decryption before required checks; compare the recipient's entire binding, including a substituted signing key with the same encryption key/ID. Both modes reject an ineligible recorded membership decision even after readmission. Missing mandatory evidence blocks; uncertainty about issuance timing or the issuer's then-known state alone need not block an archive. Later revocation alone does not invalidate history. A5 applies the local floor in both modes; A7 rechecks local policy changes. No trust promotion or active-epoch rollback. |
| [D1–D4: ancestry](device-enrollment.md#declaration-ancestry) | Bootstrap, ancestry, selections/conflicts, and recovery. Pending comparisons never become conflicts or empty selections; old ancestors cannot replace the head; resolutions cover every retained/newly discovered tip and clear the resolved conflict atomically. Retained selections survive their signer's later withdrawal without accepting new selections by that signer; invalid input cannot erase state. |
| [R1–R4: revocations](device-enrollment.md#revocation-processing) | Withdrawals, cutoff authority, recovery, and bounded validation. R1 replays preserve accepted statements without moving A/W or reauthorizing the signer. Distinguish known never-accepted bindings from missing acceptance history, and unwithdrawn status from missing withdrawal history. R3 uses the target's first acceptance and signer's first accepted withdrawal; inactive receipt cannot backdate W, later revocations cannot advance it, and timestamps/other issuers' histories cannot replace local ordering. R2–R4 atomically check authority and retain the statement/withdrawal/cutoff, including races with other withdrawals. An already withdrawn or unknown-history target never receives an invented later cutoff. Preserve accepted revocations despite later signer withdrawal. Re-evaluate incomplete candidates when evidence arrives; bounded/resumed work never suppresses independently valid withdrawals or invents authority. |
| [C1–C4: context](core.md#context-validation) | Rotation events, grant retries, and availability recovery. Unidentified event scope blocks the exchange; known unrelated scope avoids unrelated private trust requirements; affected authority/ancestry gaps block only affected exchanges. All required public evidence remains mandatory; first observation or replay of an already-addressed event, including an inherited compromise report, does not trigger repeated rotation. |
| [H1–H4 and T1–T7: activation](core.md#activation) | Activation, availability/recovery, history bridges, abuse controls, and writers. Validate every target against accepted host history; host acceptance cannot prove wrap correctness or possession of omitted keys. Bind the full list in the signed proposal, retain it unchanged on exact retries, and regenerate wraps under a fresh key after a stale proposal. Exercise every transition with a crash before/after persistence or network action; unavailable validation or throttling leaves no terminal outcome; terminal-result lookup precedes admission/eligibility checks; exact retries return the original result after membership/epoch changes. T6 reapplies retrieval/backoff guidance before another automatic availability recovery; security rotation remains prompt. Cancellation, including when a usable grant makes recovery unnecessary, survives restart, disables retransmission, and retains read-only reconciliation of late outcomes; no candidate grant or rollback. |
| [P1–P8: publication](audit.md#publication) | Publication retries, evidence, and retention/sync. Every transition, partial uploads, acknowledgment loss, absent/different repo bytes, reauthorization before each release, and late acknowledgment after stopping. Stopping preserves prior exposure facts. |
